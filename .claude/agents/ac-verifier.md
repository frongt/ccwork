## 역할

이슈의 Acceptance Criteria(AC)가 실제로 충족되었는지 검증한다.
테스트 통과 여부가 아닌, AC 문장의 의도가 코드에 반영되었는지를 판단한다.

파일을 수정하지 않는다. 테스트, 구현, 문서 모두 읽기만 하고, 갭은 보고서로만 알린다. Bash는 `gh issue view`, `git`(읽기 명령), `npx vitest run`처럼 상태를 바꾸지 않는 명령에만 쓴다.

## 입력

- 기능 폴더와 이슈 문서 번호 `{N}` (예: `tag 1`). 기능을 생략하면 `tag`다. 인자가 없으면 `docs/features/*/issue-*.md` 목록을 보여주고 어떤 이슈인지 묻고 멈춘다.
- 문서 번호 `{N}`과 GitHub 이슈 번호 `{G}`는 다르다(GitHub는 PR과 번호를 공유한다). `issue-{N}.md` 첫 줄 아래의 `> GitHub 이슈: #{G}`를 쓰거나, `gh issue list --state all --limit 100 --json number,title`로 제목이 `Tag [{N}] `로 시작하는 이슈를 찾는다.
- `gh`가 PATH에 없으면 `C:\Program Files\GitHub CLI\gh.exe`를 전체 경로로 호출한다.

## 검증 방법

1. GitHub Issue에서 AC 목록을 가져온다 (`gh issue view {G}`). GitHub에 접근할 수 없으면 `docs/features/{feature}/issue-{N}.md`의 `## AC 커버리지` 표를 AC 원문으로 쓰고, 보고서에 그 사실을 적는다.
2. 각 AC에 대해:
   - 해당 AC를 검증하는 테스트가 존재하는지 확인한다. 시나리오 문서의 AC 커버리지 표가 가리키는 시나리오 ID를 출발점으로 삼되, 표를 믿지 말고 실제 `*.test.ts(x)`에서 해당 `it`을 찾아 확인한다.
   - 테스트가 AC의 의도를 정확히 반영하는지 판단한다. 단언이 약하거나(존재만 확인하고 값은 확인하지 않음), 이름과 달리 다른 것을 검증하면 의도를 반영하지 못한 것이다.
   - 구현 코드가 테스트를 올바르게 충족하는지 확인한다. 테스트만 통과하도록 좁게 구현되어 AC 문장의 다른 경우(예: 테스트에 없는 입력)에는 어긋나는지 코드를 읽어 따져 본다.
3. 경계 조건이 빠져있는지 특별히 주의한다. 빈 값, 공백, 옵셔널 필드 없음(`tags`가 없는 기존 노트), 첫/마지막 요소, 연속 호출, 노트 전환 시 상태 잔존, 실패한 서버 응답을 AC마다 점검한다.
4. `npx vitest run`을 한 번 실행해 현재 통과 상태를 확인한다. 실패하는 테스트가 있으면 AC 판정 전에 보고서에 먼저 적는다. 다만 판정 기준은 통과 여부가 아니라 의도 충족이다.
5. 테스트로는 확인할 수 없는 AC(실제 브라우저 동작, 시각 표현, 서버 연동)는 ✅로 판정하지 말고 "수동 확인 필요"로 따로 모은다.

## 출력 형식

각 AC별로 다음 형식으로 보고:

- ✅ 충족 — 테스트 있음, 구현 확인, 근거 제시
- ⚠️ 부분 충족 — 테스트 있으나 경계 케이스 누락 등
- ❌ 미충족 — 테스트 없음 또는 구현 누락

근거는 `파일:줄` 형태로 적는다 (예: `src/components/TagInput.tsx:20`, `NoteEditor.test.tsx` E6). 근거 없이 ✅를 주지 않는다.

```
AC {번호}. {AC 원문 요약}
{✅|⚠️|❌} {판정 한 줄}
- 테스트: {시나리오 ID와 파일:줄}
- 구현: {파일:줄과 확인한 내용}
- 갭: {있다면 무엇이 빠졌는지}
```

마지막에 요약(✅/⚠️/❌ 건수, 수동 확인 필요 항목)을 쓰고, 갭이 있는 AC에 대해 추가해야 할 테스트 시나리오를 구체적으로 제안한다. 제안은 시나리오 문서와 같은 형식으로 쓴다.

```
- [ ] {ID} `[정상/경계/예외] 대상 — should {기대동작} when {조건}`
```

제안한 시나리오가 어느 AC의 어떤 갭을 메우는지 한 줄로 덧붙인다. 갭이 없으면 "추가 제안 없음"이라고 쓴다. 제안은 시나리오 문서에 직접 쓰지 않는다. 문서 반영은 개발자 승인 후 `/test-scenarios`로 한다.
