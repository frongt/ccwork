# TDD Refactor — 테스트 유지하며 코드 구조 개선

## 입력

`$ARGUMENTS`로 이슈 번호를 받는다. 예: `/tdd-refactor 1`

## 절대 규칙

- **새 기능을 추가하지 않는다** — 동작 변경 없이 구조만 개선
- **테스트 파일(`*.test.ts`, `*.test.tsx`)은 수정하지 않는다**
- **src/ 디렉토리 밖은 수정하지 않는다**
- **대상 파일 범위(git diff 결과) 밖은 수정하지 않는다**
- 테스트가 깨지면 즉시 롤백한다

---

## Step 1: 컨텍스트 읽기

1. `CLAUDE.md`를 읽어 프로젝트별 컨벤션을 파악한다:
   - 네이밍 규칙 (handle*, on*, is*, use* 등)
   - 컴포넌트 패턴 (named export, Props 인라인 선언, 슬롯 패턴 등)
   - 상태 관리 패턴 (2계층 구조, Context 패턴 등)
   - 스타일링 컨벤션 (시맨틱 토큰, 라운딩, 버튼 스타일 등)
2. `docs/features/tag/issue-{N}.md`를 읽어 이슈 범위를 확인한다

---

## Step 2: 전체 테스트 통과 확인

```bash
npm test
```

전체 PASS가 아니면 리팩토링을 시작하지 않는다. 먼저 실패를 해결한다.

---

## Step 3: 리팩토링 대상 파일 식별

```bash
git diff main...HEAD --name-only -- src/ | grep -v '\.test\.'
```

이 명령으로 이번 이슈에서 변경된 src/ 내 서비스 코드 파일만 추출한다.

---

## Step 4: 점검 기준으로 코드 검토

대상 파일을 하나씩 읽고, 아래 기준으로 리팩토링 항목을 도출한다.

### 범용 점검 기준

| 기준             | 질문                                                           |
| ---------------- | -------------------------------------------------------------- |
| 중복 제거        | 같은 로직이 반복되는가? 공통 함수로 추출할 수 있는가?          |
| 네이밍 명확성    | 변수/함수 이름이 의도를 드러내는가? 약어를 남용하지 않는가?    |
| 단일 책임        | 하나의 함수/컴포넌트가 너무 많은 일을 하는가? 분리가 필요한가? |
| 불필요한 복잡도  | 매직 넘버, 과도한 중첩, 불필요한 추상화가 있는가?              |
| CLAUDE.md 컨벤션 | 프로젝트 네이밍/패턴/스타일 규칙과 어긋나는 코드가 있는가?     |

### 출력 형식

```
## 리팩토링 대상

| # | 파일 | 항목 | 기준 | 설명 |
|---|------|------|------|------|
| 1 | TagInput.tsx | error state 로직 | 단일 책임 | 에러 판별 로직을 분리 |
| 2 | NoteEditor.tsx | handleTagsChange | 네이밍 | 즉시 PATCH 동작이 이름에 드러나지 않음 |
```

---

## Step 5: 개발자 승인

리팩토링 대상 목록을 개발자에게 보여준다.

**승인 전까지 코드를 수정하지 않는다.**
개발자가 항목을 제거하거나 추가할 수 있다.

---

## Step 6: 리팩토링 실행

승인된 항목을 하나씩 처리한다.

각 항목마다:

### 6-1. 변경 수행

하나의 리팩토링 항목만 변경한다. 여러 항목을 동시에 수정하지 않는다.

### 6-2. 테스트 확인

```bash
npm test
```

- PASS → 다음 항목으로
- FAIL → 즉시 변경을 되돌리고 다른 접근을 시도하거나 해당 항목을 건너뛴다

### 6-3. 다음 항목

모든 승인 항목을 처리할 때까지 반복한다.

---

## Step 7: 완료 보고

```
TDD Refactor 완료: Issue #{N}

리팩토링 항목: {처리}/{승인} 완료

변경 요약:
  - TagInput.tsx: 에러 판별 로직을 validateTag 반환값으로 통합
  - NoteEditor.tsx: handleTagsChange → handleTagsChangeWithPatch로 변경
  - (각 항목의 before/after 설명)

건너뛴 항목:
  - (있으면 사유와 함께 기록)

테스트 결과: {N}/{N} PASS
```
