# 휴지통 기능 PRD

> 기준 문서: [`spec-fixed.md`](./spec-fixed.md) (확정본). Out of Scope은 사용자 확정 대기 중이다.

## 1. 개요

### 요약

노트를 **삭제**하면 서버에서 지우는 대신 `deletedAt`을 기록해 휴지통에 보관하고, 사용자가 휴지통에서 **복구**하거나 **영구 삭제**(개별/비우기)할 수 있게 하는 기능이다. 사이드바 좌측 하단의 휴지통 아이콘으로 사이드바를 휴지통 뷰로 전환하며, 휴지통 노트는 메인 영역에서 읽기 전용으로 미리 본다.

### 배경 및 근거

- 현재 삭제 버튼은 확인 없이 `DELETE /notes/:id`로 즉시 영구 삭제한다. 실수로 지워도 되돌릴 방법이 없다.
- 삭제를 되돌릴 수 있게 하면 삭제에 대한 부담이 줄고 데이터 유실 위험이 줄어든다.
- 기존 CRUD 흐름(타입 → API → Context → 컴포넌트) 위에 올리는 확장이고, `Confirm` 컴포넌트가 이미 있어 확인 흐름을 재사용할 수 있다.

## 2. 사용자 스토리

- 노트 작성자로서, 노트를 삭제하면 휴지통으로 보내지길 원한다. 그래야 실수로 지워도 되돌릴 수 있다.
- 노트 작성자로서, 휴지통의 노트를 읽기 전용으로 미리 보고 싶다. 그래야 복구할 노트인지 판단할 수 있다.
- 노트 작성자로서, 휴지통의 노트를 확인 후 복구하고 싶다. 그래야 실수 없이 일반 목록으로 되돌릴 수 있다.
- 노트 작성자로서, 필요 없는 노트를 영구 삭제하거나 휴지통을 비우고 싶다. 그래야 휴지통을 정리할 수 있다.
- 노트 작성자로서, 최근에 삭제한 노트를 위에서 찾고 삭제일을 보고 싶다. 그래야 방금 지운 노트를 빨리 찾을 수 있다.

## 3. 기술 결정 (ADR)

### ADR-001: 휴지통 아키텍처 — notes 내부 deletedAt + 규칙/상태/표현 분리 (B안)

- **Status**: 확정

- **Context**:
  - 정의서(`spec-fixed.md`)가 `Note.deletedAt` 필드를 이용한 soft delete를 확정했다. 별도 `/trash` 리소스와 localStorage는 쓰지 않는다.
  - 휴지통 노트는 일반 목록, 검색 결과, 태그 필터에서 제외해야 한다. 제외 규칙이 여러 컴포넌트에 흩어지면 누락 위험이 있다.
  - 현재 `api.updateNote`는 `Partial<Note>`로 PATCH하고, `api.deleteNote`는 `DELETE`를 호출한다. `NotesContext`는 `notes` 배열 하나와 `createNote/updateNote/deleteNote`를 노출하며, `NoteList`는 `useNotes().notes` 전체를 렌더링한다.
  - 삭제·복구·영구 삭제·비우기에 모두 `Confirm`이 필요하고, 사이드바 뷰 전환과 읽기 전용 미리보기라는 새 UI 상태가 생긴다. ADR-002(규칙/상태/표현 분리)를 따른다.

- **Decision**: `Note`에 `deletedAt`을 추가하고, 로직을 **규칙 / 상태 / 표현**으로 분리한다.

  | 계층 | 파일                                                                          | 책임                                                                                                                                                                  |
  | ---- | ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | 타입 | `src/types/note.ts`                                                           | `deletedAt?: string \| null` 추가                                                                                                                                     |
  | API  | `src/api/notes.ts`                                                            | 기존 `updateNote`(PATCH)와 `deleteNote`(DELETE)를 재사용. 필요하면 `trashNote`/`restoreNote` 래퍼 추가                                                                |
  | 규칙 | `src/utils/trash.ts` (신규)                                                   | 순수 함수. `partitionNotes(notes)`(일반/휴지통 분리), `sortByDeletedAt(notes)`(최근 삭제 순 정렬)                                                                     |
  | 상태 | `src/context/NotesContext.tsx`                                                | 내부는 전체 배열을 보관하고 `notes`(일반)와 `trashedNotes`를 파생해 노출. `trashNote`, `restoreNote`, `emptyTrash`를 추가하고, `deleteNote`는 영구 삭제로 의미를 고정 |
  | 상태 | `src/hooks/useConfirmAction.ts` (신규)                                        | `Confirm`에 필요한 대기 중 액션과 확인/취소 동작을 캡슐화                                                                                                             |
  | 표현 | `src/components/TrashList.tsx`, `NotePreview.tsx`, `SidebarFooter.tsx` (신규) | props만 받는 순수 컴포넌트. 휴지통 목록(삭제일 표시, 복구/영구 삭제 버튼), 읽기 전용 미리보기, 휴지통 아이콘 영역                                                     |
  | 조립 | `src/App.tsx`                                                                 | 사이드바 뷰(`sidebarView`)와 휴지통 선택 상태 보유, `useNotes()` 호출은 조립 컴포넌트에서만. 헤더 '+ 새 노트'는 일반 목록으로 전환 후 작성 모드                       |
  | 수정 | `NoteList.tsx` / `NoteItem.tsx`                                               | 삭제 시 `trashNote` 호출 전 `Confirm` 표시                                                                                                                            |
  - 구현 순서: 타입 → 규칙(`utils/trash.ts`) → API/Context(`trashNote` → `restoreNote` → 영구 삭제/비우기) → 표현 컴포넌트 → `App` 조립.
  - 서버 저장은 기존 패턴대로 응답 후 로컬 배열을 갱신한다(재조회 없음). 복구는 `PATCH { deletedAt: null }`로 처리한다.

- **Alternatives**:
  - **A안: 인라인** — `NoteList`/`NoteEditor`/`App`에 분기를 직접 넣는다. 파일이 가장 적지만, 휴지통 제외 규칙을 검색·태그 등 소비자마다 구현해야 해서 누락 위험이 크고, 규칙을 UI 렌더링 없이 단위 테스트하기 어렵다.
  - **C안: 서버 쿼리 분리** — 일반/휴지통을 서버 쿼리로 따로 받아 배열 2개를 관리한다. 삭제·복구마다 두 배열을 동기화해야 하고, 초기 로딩이 2회 호출이며 json-server 쿼리 문법에 의존한다. 얻는 이점(서버 필터링)이 이번 데이터 규모에서는 크지 않다.

- **Consequences**:
  - (+) 휴지통 노트 제외가 Context의 파생 값 한 곳에서 끝난다. `NoteList`와 이후 검색·태그는 `notes`만 쓰면 요구사항이 자동으로 지켜진다.
  - (+) 목록 분리와 정렬을 순수 함수로 렌더링 없이 단위 테스트하고, 훅은 `renderHook`, 표현 컴포넌트는 props만으로 테스트한다.
  - (+) 데이터·API는 기존 PATCH/DELETE를 재사용해 서버(`db.json`) 변경이 필요 없다.
  - (−) 신규 파일이 늘어(`trash.ts`, `useConfirmAction.ts`, `TrashList`, `NotePreview`, `SidebarFooter`) 이번 규모에서는 구조가 다소 무겁다.
  - (−) `NotesContext`의 `deleteNote` 의미가 "즉시 삭제"에서 "영구 삭제"로 바뀌므로, 기존 호출부(`NoteList`)를 `trashNote`로 바꾸는 작업이 필요하다.
  - (+/−) 삭제/복구가 PATCH이므로 `api.updateNote`의 자동 `updatedAt` 갱신이 함께 일어난다. 복구 시 `updatedAt`을 현재 일시로 갱신하는 것은 **요구사항**이며, 별도 구현 없이 충족된다. 반면 삭제 시점에도 `updatedAt`이 바뀌어 원래 마지막 수정 시각은 보존되지 않는다.
  - (−) 휴지통 노트가 일반 `GET /notes`에 계속 포함되어 클라이언트가 전체를 받는다. 노트가 매우 많아지면 서버 필터링(C안)을 새 ADR로 다룬다.
  - (−) 기존 `Confirm`은 `blue-500` 등 Tailwind 기본색과 흰 글자를 쓰므로 디자인 시스템 Don't에 해당한다. 이 기능에서 쓰기 전에 마이그레이션(`ds-migrate`)이 필요하다.

## 4. Out of Scope

이번 범위에 포함하지 않는 항목이다. 필요해지면 별도 기능으로 기획한다.

### 휴지통 보관 정책

- 보관 기간 제한과 자동 영구 삭제(예: 30일 후 삭제), 남은 기간 표시
- 휴지통 용량 제한

### 휴지통 활용 기능

- 휴지통 내 검색, 태그 필터, 정렬 옵션 변경 (최근 삭제 순만 제공)
- 휴지통 노트 개수 뱃지, 휴지통 아이콘의 상태 표시
- 다중 선택 복구/영구 삭제 (항목 하나씩 처리)

### 휴지통 노트 편집

- 휴지통 노트의 편집 (읽기 전용 미리보기만 제공)
- 편집기에서 열린 상태로 복구하는 동작 (복구 후에도 휴지통 뷰에 머문다)

### 동작/UX

- 복구 취소(undo) 토스트, 삭제 취소 토스트
- 삭제된 노트를 원래 목록 위치로 복원하는 순서 기억
- 키보드 단축키(삭제, 복구)
- 복구 시 `updatedAt` 보존 (복구하면 `updatedAt`은 복구 시각으로 갱신되는 것이 요구사항이다)

### 데이터/서버

- 기존 `db.json` 노트 마이그레이션 (`deletedAt`이 없는 노트는 일반 노트로 처리)
- 서버 측 soft delete 구현, 별도 `/trash` 리소스, 서버 쿼리 필터링
- 낙관적 업데이트, 재조회(refetch). 기존 패턴(서버 응답 후 로컬 갱신)을 유지한다
- 서버 장애 시 재시도, 오프라인 지원, 다중 사용자/권한

### UI

- 모바일/반응형 전용 레이아웃, 다크 모드 별도 스타일
- 휴지통 아이콘 이외의 진입 경로(헤더 버튼, 단축키, 메뉴)
- 접근성 고도화 (`aria-label`, 포커스 표시 이외의 스크린리더 안내)
- 다국어 지원 (UI 문구는 한국어로 통일)

## 5. 용어 정의

`spec-fixed.md`의 "용어 정의"와 동일하다.

| 용어          | 의미                                                                                  | 코드 식별자              |
| ------------- | ------------------------------------------------------------------------------------- | ------------------------ |
| 휴지통        | 삭제된 노트를 보관하는 사이드바 뷰                                                    | `trash`                  |
| 삭제          | `deletedAt`을 기록해 일반 목록에서 숨기고 휴지통에 보관하는 것 (서버에서 지우지 않음) | `trashNote`              |
| 복구          | 휴지통 노트의 `deletedAt`을 제거해 일반 목록으로 되돌리는 것                          | `restoreNote`            |
| 영구 삭제     | 휴지통 노트 1건을 서버에서 완전히 지우는 것 (`DELETE`)                                | `deleteNote`             |
| 휴지통 비우기 | 휴지통의 모든 노트를 영구 삭제하는 것                                                 | `emptyTrash`             |
| 휴지통 노트   | `deletedAt`이 있는 노트                                                               | `note.deletedAt != null` |
| 일반 노트     | `deletedAt`이 없는 노트                                                               |                          |
