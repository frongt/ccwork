# 휴지통 기능 — 확정 요구사항 (spec-fixed)

> 초기 아이디어: "삭제하면 휴지통에 들어가고 복구할 수 있는 기능" (인터뷰로 확정)

## 개요

노트를 **삭제**하면 서버에서 지우는 대신 휴지통에 보관하고, 휴지통에서 **복구**하거나 **영구 삭제**할 수 있다.

## 용어 정의 (Ubiquitous Language)

| 용어          | 의미                                                                                         | 코드 식별자                    |
| ------------- | -------------------------------------------------------------------------------------------- | ------------------------------ |
| 휴지통        | 삭제된 노트를 보관하는 사이드바 뷰                                                           | `trash`                        |
| 삭제          | 노트에 `deletedAt`을 기록해 일반 목록에서 숨기고 휴지통에 보관하는 것 (서버에서 지우지 않음) | `trashNote`                    |
| 복구          | 휴지통 노트의 `deletedAt`을 제거해 일반 목록으로 되돌리는 것                                 | `restoreNote`                  |
| 영구 삭제     | 휴지통 노트 1건을 서버에서 완전히 지우는 것 (`DELETE`)                                       | `deleteNote` (기존 API 재사용) |
| 휴지통 비우기 | 휴지통의 모든 노트를 영구 삭제하는 것                                                        | `emptyTrash`                   |
| 휴지통 노트   | `deletedAt`이 있는 노트                                                                      | `note.deletedAt != null`       |
| 일반 노트     | `deletedAt`이 없는 노트                                                                      |                                |

## 확정 사항

### 1. 사용자

- primary user: 노트 앱의 단일 사용자 (별도 계정/권한 없음).

### 2. 저장 방식

- `Note`에 선택 필드 `deletedAt?: string`(ISO 문자열)을 추가한다. (soft delete)
- 삭제 = `PATCH /notes/:id { deletedAt }`, 복구 = `deletedAt` 제거(`null` 처리), 영구 삭제 = 기존 `DELETE /notes/:id`.
- 별도 `/trash` 리소스, localStorage 보관은 사용하지 않는다.
- 일반 목록/휴지통 목록은 클라이언트에서 `deletedAt` 유무로 나눈다.

### 3. UI

- 사이드바 **좌측 하단에 휴지통 아이콘 버튼**(`aria-label="휴지통"`)을 둔다. 누르면 사이드바가 휴지통 목록으로 전환된다.
- 휴지통 뷰에서 일반 목록으로 돌아가는 수단을 제공한다.
- 휴지통 항목을 누르면 메인 영역에 제목/내용을 **읽기 전용**으로 보여준다 (편집 불가).
- 휴지통 목록은 **최근 삭제된 순**(`deletedAt` 내림차순)으로 정렬하고, 항목에는 수정일 대신 **삭제일**(`toLocaleDateString('ko-KR')`)을 표시한다.
- 휴지통 뷰에서 헤더의 '+ 새 노트'를 누르면 **일반 목록으로 전환하고 새 노트 작성 모드**로 연다.
- 각 휴지통 항목에 **'복구'**, **'영구 삭제'** 버튼, 휴지통 뷰에 **'휴지통 비우기'** 버튼을 둔다.
- UI 문구는 한국어, 스타일은 디자인 시스템(`docs/design-system/`)을 따른다.

### 4. 최소 동작 시나리오

1. 노트 삭제 → `Confirm` 확인 → 일반 목록에서 사라지고 휴지통에 나타난다.
2. 휴지통 열기 → 노트 선택해 읽기 전용 미리보기 → '복구' → `Confirm` 확인 → 일반 목록에 다시 나타난다.
3. 휴지통에서 '영구 삭제' 또는 '휴지통 비우기' → `Confirm` 확인 → 서버에서 완전히 삭제된다.

### 5. 확인창(Confirm) 정책

- 삭제: **항상 `Confirm` 표시**.
- 영구 삭제, 휴지통 비우기: `Confirm` 표시 (되돌릴 수 없음).
- 복구: `Confirm` 표시, 확인 시에만 복구 로직 실행 (취소하면 아무 일도 일어나지 않음).

### 5-1. 복구 시 updatedAt

- 복구하면 `deletedAt`을 제거하는 동시에 `updatedAt`을 **현재 일시**로 갱신한다 (`api.updateNote`의 자동 갱신 사용).

### 6. 경계 조건

- 휴지통 보관 기간 제한과 **자동 영구 삭제는 없다**. 사용자가 직접 지우거나 비울 때만 삭제된다.
- 휴지통이 비어 있으면 빈 상태 문구를 보여준다.
- 선택 중인 노트를 삭제하면 선택 상태를 해제한다.
- 휴지통에서 노트를 복구하면 **휴지통 뷰에 머물고**, 읽기 전용 미리보기만 비운다 (복구한 노트는 목록에서 사라짐).

### 7. 에러 처리

- 기존 관례를 따른다: API가 `Error`를 throw → Context 전파 → 호출 컴포넌트가 `try/catch`에서 `alert`로 표시.
- 서버 응답 후 로컬 상태를 갱신한다 (낙관적 업데이트, refetch 없음).

### 8. 타 기능과의 관계

- 휴지통 노트는 **일반 목록, 검색 결과, 태그 필터에서 제외**한다.
- 태그는 노트에 그대로 보존되어 복구 시 함께 돌아온다.

## 범위 밖 (후보, PRD에서 확정)

- 휴지통 내 검색/태그 필터, 휴지통 자동 만료, 다중 선택 복구, 복구 취소(undo) 토스트, 휴지통 노트 편집.

## 성능

- json-server 규모의 소량 데이터를 가정하며 별도 제약은 없다.
