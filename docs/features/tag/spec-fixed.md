# 태그 기능 정의서 (확정본)

> 원본: `spec-original.md` 에 질의응답(11개)으로 확정한 내용을 더해 정리한 문서.

## 기능 개요

노트에 태그를 추가하고 관리할 수 있다.

## 기능 요구사항

- 노트에 태그를 추가할 수 있다
- 노트에 추가된 태그를 삭제할 수 있다
- 태그 목록을 노트 상세 화면에서 확인할 수 있다
- 왼쪽 노트 목록에서 태그가 있는 노트는 별도로 표시해준다

## 데이터 구조

- `Note.tags?: string[]` — 노트 객체 안에 문자열 배열로 저장한다.
- 옵셔널 필드이다. 기존 노트(`db.json`)에는 `tags`가 없으므로 사용처에서 `note.tags ?? []`로 처리한다.
- `db.json`은 수정하지 않는다.
- 태그는 추가한 순서대로 배열에 유지한다.

## 태그 입력 규칙

| 항목      | 규칙                                                                  |
| --------- | --------------------------------------------------------------------- |
| 공백 처리 | 입력값은 앞뒤 공백을 trim하여 저장한다                                |
| 빈 값     | 빈 값/공백만 입력하면 무시한다 (메시지 없음)                          |
| 중복      | trim 후 대소문자 무시로 비교한다. 저장은 처음 입력한 표기 그대로 한다 |
| 중복 시   | 입력창 아래에 "이미 있는 태그입니다" 안내 문구를 표시한다             |
| 길이      | 태그 하나당 최대 50자. 초과 시 추가하지 않고 안내 문구를 표시한다     |
| 개수      | 노트당 최대 10개. 초과 시 추가하지 않고 안내 문구를 표시한다          |
| 특수문자  | 제한 없음                                                             |

## UI 명세

### NoteEditor (노트 상세/편집 화면)

- 제목 입력 바로 아래에 **"태그 추가"** 버튼을 둔다. 회색 계열(`text-muted-foreground`, `border-border` 등)로 눈에 띄지 않게 한다.
- 버튼을 누르면 버튼 오른쪽에 태그 입력창이 나타나고, 버튼명은 **"닫기"**로 바뀐다.
- "닫기"를 누르면 입력창이 사라지고 버튼은 "태그 추가"로 돌아온다.
- 입력창에서 **Enter**를 누르면 태그가 한 개씩 추가된다. 폼 submit은 막는다(`preventDefault`).
- 추가되면 입력창은 비워지고, 열린 상태를 유지한다 (연속 입력 가능).
- 추가된 태그는 입력 영역 아래에 실시간으로 표시한다.
- 태그가 하나도 없으면 목록 영역에 아무것도 표시하지 않는다.
- 태그 목록은 `flex-wrap`으로 여러 줄에 걸쳐 표시한다.

### Tag 컴포넌트 (`src/components/Tag.tsx`)

- named export `Tag`, props 인터페이스 `TagProps`. 데이터 의존 없는 순수 표현 컴포넌트.
- 둥근 박스 형태, 앞에 태그 아이콘, 라벨 텍스트, 삭제용 `x` 버튼으로 구성한다.
- 삭제는 `onDelete` 콜백으로 부모에 위임한다.
- 긴 태그는 박스 최대 너비를 제한하고 `truncate`로 말줄임 처리한다. 전체 이름은 `title` 속성으로 호버 시 보여준다.

### 삭제 버튼 (`x`)

- DOM에는 항상 존재하며 평소에는 투명하다.
- 태그에 마우스를 올리거나(`group-hover`) 버튼에 키보드 포커스가 오면(`focus`) 보인다.
- `aria-label="{태그명} 태그 삭제"`를 단다.
- 터치 기기 대응(항상 표시)은 이번 범위에서 제외한다.

### NoteItem (왼쪽 노트 목록 카드)

- 태그가 1개 이상인 노트는 작은 태그 아이콘과 개수(예: 🏷 3)를 회색으로 표시한다.
- 태그가 없으면 아무것도 표시하지 않는다.
- 개수는 서버에 저장된 값 기준이다. 편집 중인 미저장 태그는 반영되지 않는다.

## 저장 동작

- 태그 추가/삭제는 NoteEditor 로컬 `tags` state에 먼저 반영한다.
- 기존 **"저장"** 버튼을 눌렀을 때 `title`, `content`, `tags`가 함께 서버에 반영된다. (수정: PATCH, 생성: POST)
- 새 노트 작성 중에도 같은 방식으로 동작한다. 새 노트 생성 시 `tags`가 없으면 `[]`를 보낸다.
- 서버 응답 후 Context의 로컬 배열을 갱신한다 (재조회 없음, 기존 패턴 유지).

## 노트 전환 시 동작

- `selectedNoteId`/`isCreating`이 바뀌면 `title`, `content`, `tags`를 함께 리셋한다.
- 태그 입력창은 닫힌 상태로 돌아가고, 입력 중이던 텍스트와 안내 문구도 초기화한다.
- 미저장 변경에 대한 확인창은 두지 않는다 (조용히 버림).

## 구현 순서

CLAUDE.md의 확장 순서를 따른다.

1. `types/note.ts` — `tags?: string[]` 추가, 기존 "tags 필드는 아직 없음" 주석 정리
2. `api/notes.ts` — 생성/수정 payload에 `tags` 반영
3. `context/NotesContext.tsx` — `addNote`/`editNote`가 `tags`를 받도록 확장
4. `components/Tag.tsx` — 신규
5. `components/NoteEditor.tsx` — 태그 추가 버튼/입력창/목록, 유효성, 리셋
6. `components/NoteItem.tsx` — 태그 아이콘 + 개수 표시

TDD로 진행하며, 태그가 없는 기존 노트를 열어도 에러가 나지 않는지 테스트에 포함한다.

## 비고

- 태그는 문자열로 저장한다
- 중복 태그는 허용하지 않는다
- UI 문구는 한국어로 통일한다
