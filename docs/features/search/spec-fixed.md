# 노트 검색 기능 정의서 (확정본)

> 원본: `spec-original.md` 에 질의응답(10개)으로 확정한 내용을 더해 정리한 문서.

## 기능 개요

노트 목록 상단에서 입력창으로 노트를 검색한다.

## 기능 요구사항

- 왼쪽 노트 목록 상단에 검색창을 추가한다.
- 한 라인에 선택박스/입력창/검색버튼으로 컴포넌트를 구성한다.
- 선택박스 옵션 목록은 전체/제목/내용/태그이다.
- Enter 또는 검색 버튼을 누르면 목록이 필터링된다.
- 앞, 뒤 공백은 trim 처리한다.
- 대소문자를 구분하지 않는다.

## 선행 조건

- 태그 기능(`docs/features/tag/spec-fixed.md`)의 `Note.tags?: string[]`에 의존한다. 태그 검색을 테스트하려면 태그 기능이 먼저 반영되어 있어야 한다.

## 검색 규칙

| 항목      | 규칙                                                                                                 |
| --------- | ---------------------------------------------------------------------------------------------------- |
| 매칭 방식 | 부분 일치(`includes`). 검색어를 trim하고 대소문자를 무시하여 비교한다                                |
| 제목      | 제목에 검색어가 포함되면 일치                                                                        |
| 내용      | 내용에 검색어가 포함되면 일치                                                                        |
| 태그      | 노트의 태그 중 하나라도 검색어를 포함하면 일치. 태그가 없는 기존 노트는 `note.tags ?? []`로 처리한다 |
| 전체      | 제목 OR 내용 OR 태그 중 하나라도 일치하면 결과에 포함                                                |
| 정렬      | 일치 필드에 따른 정렬 없이 기존 노트 순서를 유지한다                                                 |
| 빈 검색어 | trim 후 빈 문자열이면 필터를 해제하고 전체 목록을 보여준다. 선택박스 값은 유지한다                   |

## UI 명세

### SearchBar (`src/components/SearchBar.tsx`, 신규)

- named export `SearchBar`, props 인터페이스 `SearchBarProps`.
- 사이드바(노트 목록) 상단에 한 줄(`flex`)로 배치한다: `[선택박스] [입력창] [검색 버튼]`
- **선택박스**
  - 옵션과 순서: 전체 → 제목 → 내용 → 태그, 기본값은 "전체"
  - `aria-label="검색 대상"`, 고정 너비
- **입력창**
  - placeholder: "검색어를 입력하세요"
  - `aria-label="검색어"`, `min-w-0 flex-1`로 남은 폭을 차지하고 줄어들 수 있게 한다
  - Enter로 검색을 실행한다
- **검색 버튼**
  - 돋보기 아이콘만 표시한다 (텍스트 없음)
  - `aria-label="검색"`, `cursor-pointer hover:opacity-75`
- 색상은 기존 시맨틱 토큰(`border-border`, `bg-card` 등)을 사용한다.
- **건수 문구**
  - 검색창 하단 **좌측**에 옅은 회색(`text-muted-foreground`)의 작은 글씨로 "검색 결과 N건"을 표시한다.
  - 확정된 검색어가 있을 때(trim 후 비어 있지 않을 때)만 표시한다. 필터가 없거나 해제된 상태에서는 표시하지 않는다.
  - 결과가 0건이어도 "검색 결과 0건"을 표시한다.
  - N은 `notes`에서 확정 조건으로 걸러낸 개수이다.

### NoteList

- 확정된 검색 조건을 props로 받아 `notes`를 필터링해 렌더링한다.
- early return 순서: `loading` → `error` → 노트 없음("노트가 없습니다") → 검색 결과 없음("검색 결과가 없습니다") → 본문
- 노트가 아예 없는 경우와 검색 결과가 0건인 경우를 구분한다.

## 상태 관리

- `SearchBar`가 선택박스 값과 입력 중인 텍스트를 **로컬 `useState`**로 갖는다.
- Enter 또는 검색 버튼을 눌렀을 때만 `onSearch({ field, keyword })`로 확정된 조건을 `App`에 올린다.
- `App`이 확정 조건(`field`, `keyword`)을 `useState`로 들고 `NoteList`에 props로 내려 필터링한다. (UI 상태는 `App`, 폼 입력은 로컬이라는 기존 패턴)
- 타이핑만 하고 Enter/검색 버튼을 누르지 않으면 목록은 바뀌지 않는다.
- **선택박스를 바꿔도** 필터는 바뀌지 않는다. Enter/검색 버튼에서만 적용된다. 입력 중인 값과 적용된 조건이 잠시 어긋날 수 있다.
- NotesContext에는 검색 상태를 두지 않는다.

## 노트 변경 시 동작

- 필터가 걸린 상태에서 노트를 생성/수정/삭제해도 필터 조건은 유지된다.
- 목록은 `notes`와 확정 조건에서 매번 파생해 계산한다 (별도 저장 안 함).
- 저장 후 조건에 맞지 않게 된 노트는 목록에서 사라지지만, 편집 화면(`selectedNoteId`/`isCreating`)은 그대로 유지한다.
- 건수 N도 같은 파생 계산에 따라 함께 바뀐다.

## 필터 해제

- 별도의 지우기(x) 버튼이나 초기화 버튼은 두지 않는다.
- 입력창을 비우고 Enter(또는 검색 버튼)를 누르면 필터가 해제된다.

## 구현 순서

CLAUDE.md의 데이터 흐름 계층을 따른다.

1. 필터링 함수 — 필드/검색어를 받아 노트를 걸러내는 순수 함수 (trim, 대소문자 무시, `tags ?? []`)
2. `components/SearchBar.tsx` — 신규. 로컬 state, `onSearch`, 건수 문구
3. `App.tsx` — 확정 조건 state 추가, `SearchBar`/`NoteList` 연결
4. `components/NoteList.tsx` — 조건 props로 필터링, "검색 결과가 없습니다" 분기

TDD로 진행하며, 태그가 없는 기존 노트에 대해 에러 없이 동작하는지 테스트에 포함한다.

## 비고

- 실시간(타이핑 중) 필터링은 하지 않는다.
- UI 문구는 한국어로 통일한다.
